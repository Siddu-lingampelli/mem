Install ¶

Requires Node.js 18+ and any shell with a history file

npm install -g mem-terminal

Verify

mem --version
# mem v2.2.5

Quick Start ¶ 
mem "docker compose"        # direct search
mem search "npm run build"  # explicit search subcommand
mem stats                   # command usage statistics
mem bench                   # benchmark parse & search
mem recent                  # last 20 commands
mem --help                  # help

On the very first bare mem run, a welcome banner prints once and a flag file (~/.mem-welcome) is written so it never re-fires. Later bare mem shows help

Search ¶

Results are deduped, ranked by relevance, with usage frequency and recency

mem "git"
# → 16 matches (showing top 20)
#   git status              • used 12× • recent
#   git push origin main    • used 8×
#   git commit -m "fix

Use --all for every match, or -n/--max for a custom limit

mem "git" --all                # show all matches
mem "docker" -n 5              # show only 5 results

The --shell flag lives on the subcommands (search, stats, bench, recent). For a bare mem "query the shell is always auto

Cross-shell history ¶

By default mem reads your PowerShell / PSReadLine history (common on Windows). If you use Bash, Zsh, or Fish (e.g. Git Bash on Windows), pick the source shell explicitly so mem reads the log you actually run

auto powershell (pwsh bash zsh fish 
mem search "git" --shell bash    # read .bash_history
mem search "git" --shell zsh     # read .zsh_history
mem search "git" --shell fish    # read fish_history
mem stats        --shell bash
mem recent       --shell zsh
mem bench        --shell fish

auto prefers PSReadLine, then falls back Bash → Zsh → Fish. Explicit shell names bypass PSReadLine entirely — fixes the case where a Windows user with Git Bash always got the PSReadLine history regardless of HISTFILE

On Windows, Git Bash rewrites /tmp/ paths to C:/Users/.../Temp/. Export HISTFILE with a Windows-style path (or use --shell) to target a specific log

How it works ¶

mem reads your PSReadLine (ConsoleHost_history.txt), Bash (.bash_history), Zsh (.zsh_history), or Fish (fish_history) history, newest-first — auto-detects which file exists, with graceful fallback between shells

  • Encoding — auto-detects UTF-8 BOM, UTF-16 LE BOM, or plain UTF-8
  • Search — token-aware fuzzy matching with Levenshtein distance scoring
  • Ranking — relevance score → usage frequency → alphabetical
  • Deduplication — identical commands merged with usage count
  • Noise filtering — self-commands (mem, history) and single-char commands filtered

Search engine ¶

A custom, zero-dependency engine (not Fuse.js). Two phases

Preprocess

  • Dedupe — case-insensitive; each keeps a usage count
  • Noise filter — drops mem, history, clear, cls, exit, single-char, non-alnum-only
  • Tokenise — lowercase alphanumeric split
  • Index — newest-first order preserved

Score

Each query word is scored against each cached entry token. Lower = better

Bounded Levenshtein: length-gap early exit + two-row DP. Token buffers are pre-allocated and pooled for any token strictly shorter than 64 characters; longer tokens allocate per call. Row-min termination keeps distant comparisons cheap

Entries with average score below 0.4 pass the filter

Match typePenaltyExample
Exact token0.00compose in docker compose
Levenshtein distance 10.05docer → docker
Levenshtein distance 20.12docor → docker
Query prefix0.10doc → docker
Token prefix0.15com → compose
Token substring0.25ai in claim
Command prefix0.35git in git push
Command global substring0.50run in npm run build

Parsers ¶

Every reader is idempotent, newest-first, limit-capped, and swallows read errors (returns []

PowerShell / PSReadLine

Path priority from getHistoryFilePath

  1. $PSREADLINE_HISTORY_FILE env var (if set, non-empty
  2. %USERPROFILE%\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt (WinPS 5.1
  3. %USERPROFILE%\AppData\Roaming\Microsoft\PowerShell\PSReadLine\ConsoleHost_history.txt (PS 7+ / pwsh
  4. %USERPROFILE%\AppData\Roaming\Microsoft\PowerShell\PSReadLine\Visual Studio Code Host_history.txt (VS Code host
  5. None exist → returns PS 7+ default so caller can error gracefully

detectEncoding(buffer: UTF-8 BOM (EF BB BF) → "utf8; UTF-16 LE BOM (FF FE) → "utf16le; else "utf-8. Leading U+FEFF stripped

Bash

Honors $HISTFILE, then tries ~/.bash_history, ~/.sh_history. Per-line HISTTIMEFORMAT detection via ^#[0-9]{8,}\s*$ (digit-only, avoids \d matching Unicode digits). Multiline commands in timestamp mode preserved; in plain mode, one line = one command

Zsh

Honors $HISTFILE, then ~/.zsh_history, ~/.histfile. Format : :; via ^:\s*\d+:\d+;(.*)$. Non-matching lines kept as raw commands. Semicolons inside commands handled (regex anchored at start

Fish

$XDG_DATA_HOME/fish/fish_history, else ~/.local/share/fish/fish_history. YAML-like - cmd / when / paths parsing, multiline continuation support

Router

shell = "powershell"|"bash"|"zsh"|"fish" -> that reader only
shell = "auto" -> PSReadLine; if empty -> Bash -> Zsh -> Fish

Explicit shells bypass PSReadLine intentionally — fixes a Windows + Git Bash user always getting PowerShell history despite $HISTFILE

Ranking ¶

Results are sorted, then grouped by match category for display

Sort

  1. Score — relevance, with a 0.01 epsilon so near-ties fall through
  2. Frequency — usage count, descending
  3. Alphabetical — stable tiebreak

Display categories

The score is bucketed into three labels for the print output

  • Exact — score is 0 (perfect match
  • Fuzzy — score ≤ 0.12 (Levenshtein ≤ 2 with prefix bonus
  • Similar — score > 0.12 but still below the threshold; rendered as Did you also mean suggestions, deduped by first word

The recent badge marks commands whose most recent use is in the newest 25% of the history file

Welcome persistence ¶

First-run boxed banner (&acut;┌───┐ box, w=36) showing version + tagline + quickstart examples + shell checkmarks + Run mem --help anytime

  • Persistence: writes empty ~/.mem-welcome flag file (best-effort — try/catch, no diagnostic
  • In-process memo (shownThisProcess): if the flag write fails (read-only HOME, sandbox, permission denied), the banner still won't re-fire for the rest of that process
  • hasSeenWelcome = shownThisProcess || existsSync(FLAG_FILE
  • Returns Promise (synchronous body) — signature preserved so a future "press any key" gate can layer on without changing call sites

History note (in source comments): v2.2.3–2.2.4 removed a "Press Enter to continue" prompt that hung on non-TTY stdin (MINGW64/msys/spawned processes

Startup mechanics ¶

How cli.ts handles the edge cases

  • isMain guard: fileURLToPath(import.meta.url) === resolve(process.argv[1]) — so cli.ts is importable for tests without auto-running
  • Custom help via program.helpInformation = () => paint(customHelp()) — overrides Commander's default with ANSI box
  • Custom --version/-V pre-parsed before program.parse to dodge Commander's help-on-version hijack
  • exitOverride + typed catch: commander.helpDisplayed → exit 0; any other → error + help + exit 1

Exported helpers (used by tests

stripAnsi, paint, parseCount(val, fallback?), parseShell(val, runSearch(query, showAll?, maxCount?, shell?)

parseCount rejects NaN and < 1, returning the fallback. Note runRecent's parseCount(opts.max, 20) ?? 20 — the trailing ?? 20 is dead defensive code (parseCount already returns the fallback

Strengths ¶
  1. Minimal surface — one prod dep, 1.3K LoC of source, ~100KB packed
  2. Strict TS — noUnusedLocals/Parameters/noImplicitAny prevent dead code and implicit any
  3. Tested — 202 tests across all 4 shells, 25 secret patterns, category grouping, CLI parsing
  4. Correct encoding handling — UTF-8/UTF-16 LE BOM auto-detect
  5. Fast search — bounded Levenshtein with pre-allocated buffers, module-level, zero per-call alloc for ≤64-char tokens
  6. Security-by-default — secrets masked on every display path, never stored
  7. Portable — cross-shell auto-detection with explicit override; honors standard env vars (HISTFILE, XDG_DATA_HOME, PSREADLINE_HISTORY_FILE
  8. Testable — isMain guard makes cli.ts import-safe; helpers (stripAnsi, paint, parseCount, parseShell) exported for direct unit testing

Observations ¶

Not requested, noted for reference

  • output.ts empty-state suggestion list is hardcoded to 8 common commands — source comment flags it as a candidate for drawing from preprocessed top-N instead
  • cli.ts runRecent: parseCount(opts.max, 20) ?? 20 — trailing ?? 20 is dead (parseCount already returns the fallback). Cosmetic noise, not a bug
  • welcome.ts showWelcome is async-typed with a synchronous body — intentional forward hook for a future keypress gate; currently never awaited meaningfully
  • secrets.ts Bitbucket pattern (BB&hellip, 28-char suffix) and Discord pattern (3-dot format) are length-anchored — could miss tokens outside those exact lengths, but match real formats
  • vercel.json + docs/ are untracked; consider committing (with a site/ note) or documenting they're deploy-only and excluded from the npm pack
  • Per CLAUDE.md, a graphify-out/ knowledge graph is referenced but does not exist yet — graphify update . would generate it

Deploy on Vercel ¶

This docs page is a static site — zero build, zero runtime. Two ways to host it on Vercel

Option A — Root Directory = docs (recommended

  1. Vercel dashboard → Project → Settings → General → Root Directory → set to docs
  2. Framework Preset: Other · Build Command: (none · Output Directory: (leave blank
  3. Deploy. index.html serves at the root

Option B — repo-root vercel.json

The vercel.json at the repo root pins the project to static mode and points the output directory at docs/ 

{
  "outputDirectory": "docs",
  "buildCommand": "",
  "installCommand": "",
  "cleanUrls": true,
  "trailingSlash": false

With Option B no dashboard settings change is required — import the repo and deploy

Prefer Option A when the repo root also hosts the npm package source — Vercel then only ever sees the static docs, never your src/ or node_modules/

Local preview

npx serve docs
# or
python -m http.server -d docs 8080
