Terminal history, searched.

Never lose a terminal command.

mem searches your shell history across PowerShell, Bash, Zsh, and Fish — instantly, fuzzy, locally. No cloud. No setup.

npm install -g mem-terminal See it in action →

Why mem?

You run hundreds of commands a day. Some you remember. Most you don't. mem finds them in milliseconds.

⚡ Instant

Fuzzy keyword search across your entire shell history. Typo-tolerant. Sub-100ms on most machines.

🔒 Private

Reads files you already have. Never uploads. API keys and tokens auto-masked in output.

🌐 Cross-shell

PowerShell, Bash, Zsh, Fish — auto-detected, with explicit override when needed.

📦 Tiny

One runtime dependency. ~30 kB installed. No daemon, no service, no background process.

Install

Requires Node.js 18+ and any shell with a history file.

npm install -g mem-terminal

Verify:

mem --version
# mem v2.2.6

Quick Start

mem "docker compose"          # direct search
mem search "npm run build"    # explicit subcommand
mem stats                     # command usage statistics
mem bench                     # benchmark parse & search
mem recent                    # last 20 commands
mem --help                    # full help
i

On the first bare mem run, a welcome banner prints once and a flag file (~/.mem-welcome) is written so it never re-fires. Later bare mem shows the help page.

Features

  • Fuzzy match — typo-tolerant with bounded Levenshtein distance
  • Relevance ranking — score → frequency → alphabetical
  • Deduplication — identical commands merged with usage count
  • Recency badge — recent commands highlighted
  • Match categories — Exact / Similar / "Did you also mean?"
  • Secret masking — 25+ token patterns auto-redacted on display
  • Cross-shell — PowerShell, Bash, Zsh, Fish auto-detected
  • BOM-aware — UTF-8 / UTF-16 LE history files
  • NO_COLOR — respects the no-color.org standard
  • Zero config — works out of the box

Search

Results are deduplicated, ranked by relevance, and annotated with usage frequency and recency.

mem "git"
# → 16 matches (showing top 20)
#   git status              • used 12× • recent
#   git push origin main    • used 8×
#   git commit -m "fix"

Use --all for every match, or -n / --max for a custom limit:

mem "git" --all                # show all matches
mem "docker" -n 5              # show only 5 results

Cross-shell history

By default mem reads your PowerShell / PSReadLine history (common on Windows). If you use Bash, Zsh, or Fish (e.g. Git Bash on Windows), pick the source shell explicitly.

auto powershell bash zsh fish 
mem search "git" --shell bash    # read .bash_history
mem search "git" --shell zsh     # read .zsh_history
mem search "git" --shell fish    # read fish_history
mem stats        --shell bash
mem recent       --shell zsh
mem bench        --shell fish

auto prefers PSReadLine, then falls back Bash → Zsh → Fish. Explicit shell names bypass PSReadLine entirely — fixes the case where a Windows user with Git Bash always got the PSReadLine history regardless of HISTFILE.

Secret masking

API keys, tokens, and passwords in your history are automatically masked on every display path. Only the first 4+ characters are shown; the rest is replaced with ********.

Philosophy: a false positive is a cosmetic annoyance; a missed secret is a leak. So mem errs on the side of masking.

How it works

mem reads your terminal history file, runs a token-aware fuzzy search with bounded Levenshtein distance, and prints grouped, color-coded results with secrets masked.

cli.ts
  └─ isMain guard → runs only when executed, not imported
  └─ program.parse()
       └─ positional "query" → runSearch()

runSearch()
  ├─ readHistory(limit, shell)     # shell router
  │    ├─ "powershell" → PSReadLine
  │    ├─ "bash"       → .bash_history
  │    ├─ "zsh"        → .zsh_history
  │    ├─ "fish"       → fish_history
  │    └─ "auto"       → PSReadLine → Bash → Zsh → Fish
  │
  ├─ search(entries, query)        # search engine
  │    ├─ preprocess()             # dedupe, tokenize, noise-filter
  │    └─ searchCached()           # score, rank, threshold
  │
  └─ print(results, query)         # output renderer
       ├─ maskSecrets()            # hide API keys, tokens
       ├─ highlightCmd()           # bold+magenta matched words
       └─ group: Exact → Similar → "Did you also mean?"

The key optimization: preprocess() runs once; searchCached() is O(n) per query and reusable. The bench command exploits this to run 5 queries over one cached set.

History parsers

Every reader is idempotent, newest-first, limit-capped, and swallows read errors (returns []).

PowerShell / PSReadLine

Path priority:

  1. $PSREADLINE_HISTORY_FILE env var (if set and non-empty)
  2. %USERPROFILE%\...\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt (WinPS 5.1)
  3. %USERPROFILE%\...\PowerShell\PSReadLine\ConsoleHost_history.txt (PS 7+)
  4. %USERPROFILE%\...\PSReadLine\Visual Studio Code Host_history.txt (VS Code)

Encoding: Auto-detects UTF-8 BOM (EF BB BF), UTF-16 LE BOM (FF FE), or falls back to UTF-8. Leading U+FEFF character is stripped.

Bash

Honors $HISTFILE, then tries ~/.bash_history, ~/.sh_history. Supports both plain mode (one command per line) and HISTTIMEFORMAT mode (lines prefixed with #[0-9]{8,}). Multiline commands in timestamp mode are preserved.

Zsh

Honors $HISTFILE, then ~/.zsh_history, ~/.histfile. Parses the extended history format: : <timestamp>:<duration>;<command>. Non-matching lines are kept as raw commands.

Fish

Reads from $XDG_DATA_HOME/fish/fish_history, else ~/.local/share/fish/fish_history. Parses the YAML-like format with - cmd:, when:, and paths: fields, including multiline command continuation.

Search engine

A custom, zero-dependency engine (no Fuse.js). Two phases:

Preprocess

  • Deduplication: Case-insensitive; identical commands merged with usage count
  • Noise filter: Drops mem, history, clear, cls, exit, single-character commands, non-alphanumeric-only commands
  • Tokenization: Lowercase alphanumeric split on [^a-z0-9]+
  • Index: Newest-first order preserved

Scoring

Each query word is scored against each cached entry's tokens. Lower score = better match.

Match typePenaltyExample
Exact token0.00compose in docker compose
Levenshtein distance 10.05docer → docker
Levenshtein distance 20.12docor → docker
Query prefix0.10doc → docker
Token prefix0.15com → compose
Token substring0.25ai in claim
Command prefix0.35git in git push
Command global substring0.50run in npm run build

Bounded Levenshtein

Swift-exits when |a.length − b.length| > maxDist (returns no-match immediately). Two-row DP with pre-allocated buffers for tokens ≤64 chars — zero per-call allocation on the hot path. Row-min early termination keeps distant comparisons cheap. Only invoked for query words ≥4 characters.

Threshold & sort

Entries with average score below 0.4 pass the filter. Sorted by: score (epsilon 0.01) → frequency descending → alphabetical. Empty query or "all", "*", "everything" keywords return all entries.

Scoring & ranking

Display categories

The aggregate score is bucketed into three labels:

CategoryScore rangeDisplay
Exact0Listed under "Exact"
Fuzzy0 < score ≤ 0.12Listed under "Similar"
Similar0.12 < score < 0.4Listed under "Did you also mean?" (deduped by first word, max 5)

Recency badge

Commands whose most recent use is in the newest 25% of the history file get a "recent" badge. The threshold is max(1, floor(totalEntries × 0.25)).

Metadata per result

Each result shows usage count (if >1), shell source (if explicitly selected), and recency — all in dimmed text.

Output & colors

Color gate: if NO_COLOR is set (any value), all ANSI is disabled. Otherwise, colors activate when stdout is a TTY. Piped output is plain text.

ANSI palette

CodeUsage
\x1b[0mReset
\x1b[1mBold (matched words)
\x1b[2mDim (separators, metadata, non-matching parts)
\x1b[32mGreen (match count header)
